# CyberDefender Roadmap 2026–2036 v1

This is a staged engineering roadmap. Dates are planning ranges, not delivery promises.

## Stage 0 — current closure (now)

- H1D9 software PRE-LAB preserved; real disposable-machine restore remains UNVERIFIED.
- Catalog v1.1: 2000 definitions independently validated; no lifecycle promotion.
- Response Control Plane: simulation-only foundation.
- NDR v0.0: synthetic/observe foundation with 60 targeted tests.
- Recorded final Windows regression: 92 PASS / 0 FAIL / 0 UNVERIFIED.

## Stage 1 — Polyglot + Probabilistic Intelligence foundation

- adopt language ownership policy
- keep Python prototype contracts stable
- Rust deterministic probability/fusion core, no AI authority
- Go bounded edge telemetry/envelope/collector foundation
- golden cross-language fixtures
- no live blocking

## Stage 2 — Windows/USB/device telemetry

- C# adapter for ETW/EventLog/PnP/device metadata where justified
- Rust local device identity and process/file correlation
- removable media insertion/mount/copy/execute chain
- HID/NIC/device-class anomaly contracts
- simulation-only response proposals

## Stage 3 — NDR v0.1 live OBSERVE

- authenticated edge collector
- flow/DNS/TLS metadata as available
- low-and-slow/distributed recon
- approved scanner context
- cross-host correlation and graph
- bounded memory/backpressure
- no blocking until lab validation

## Stage 4 — AI Analyst v0.1 hardened

- AI outside TCB
- deterministic probability engine supplies scores
- strict advisory schema + counter-evidence + abstention
- RAG/tool/memory isolation
- prompt/tool/context poisoning corpus
- no privileged tools

## Stage 5 — controlled lab containment

Only in approved disposable lab:
- process/file quarantine
- network-limited containment
- endpoint isolation
- independent verification
- rollback/recovery
- protected-target denial

## Stage 6 — distributed enterprise architecture

- Go fleet/edge services
- signed device identity/attestation
- multi-tenant control plane
- SIEM/SOAR/XDR interoperability
- horizontal scaling benchmarks
- offline/local protection

## Stage 7 — native specialization

Use C/C++ only where justified by:
- vendor SDK/driver requirement
- packet/telemetry performance proven by benchmark
- ML/native inference bridge
- kernel/firmware/eBPF boundary

All C/C++ components require narrow ABI, fuzzing, compiler hardening and sanitizer/static-analysis gates.

## Stage 8 — crypto agility / PQC

- crypto inventory
- algorithm identifiers/versioning in contracts
- hybrid/PQC migration planning
- signed update-chain agility
- no custom cryptography

## 2031–2036 posture target

CyberDefender should be able to lose AI/cloud/Python services and still retain deterministic local detection, admission, safety and minimum protection. AI becomes an accelerator, not a single point of security authority or availability.
